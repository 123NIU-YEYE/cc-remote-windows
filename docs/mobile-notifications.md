# 在手机上接收任务通知

[English](mobile-notifications_en.md) · [返回首页](../README.md) · [服务端配置](configuration.md)

cc-remote 可以通过浏览器的 **Web Push** 提醒你任务完成、失败、中断或等待回答。它需要服务端开启推送、手机浏览器完成订阅，以及系统允许通知。电脑上允许了通知，不会自动替手机授权。

## 支持方式

| 设备 | 使用方式 | 需要满足的条件 |
|---|---|---|
| iPhone / iPad | Safari 添加到主屏幕，再从图标打开 | iOS/iPadOS 16.4 或更新版本、HTTPS、用户允许通知 |
| 安卓 | 支持 Web Push 的浏览器，例如 Firefox 或 Chrome | HTTPS、浏览器和系统允许通知、推送服务网络可达 |
| 微信等应用内浏览器 | 使用系统浏览器打开网站 | 内嵌浏览器不保证提供完整的 Web Push 能力 |

浏览器通知会出现在系统通知栏或锁屏；横幅、声音及后台行为由系统设置决定。它使用网页推送通道，实际表现也受手机省电策略和网络影响。

## 第一步：确认服务端已启用 Push

部署者需要在 Relay 的外部配置中设置以下三项，并通过原有部署流程使配置生效：

| 配置项 | 用途 |
|---|---|
| `PUSH_VAPID_PUBLIC_KEY` | 供浏览器订阅使用的 VAPID 公钥 |
| `PUSH_VAPID_PRIVATE_KEY` | 与公钥配套的私钥文件绝对路径，由 Relay 用户读取 |
| `PUSH_VAPID_SUBJECT` | 联系 URI，使用有效的 `mailto:` 或 `https://` 地址 |

私钥保存在源码和发布目录之外，更新时保留同一密钥。登录后，`/api/push-config` 返回 `enabled: true` 表示服务端已开启；它不代表手机已经订阅或实际收到通知。完整参数见[配置说明](configuration.md)。

普通用户无需生成自己的密钥，直接使用部署者提供的 HTTPS 网站。

## 第二步：在手机上开启

### iPhone / iPad

1. 在 **Safari** 打开你的 cc-remote HTTPS 网址。
2. 点击「分享 → 添加到主屏幕」。
3. 回到主屏幕，从新建的 cc-remote 图标打开并登录。
4. 打开网页右上角「⋮ → 桌面通知」。这个设置也适用于手机。
5. 选择「通用提醒」或「显示会话名称」，在系统弹窗中允许通知。

仅保留一个普通 Safari 标签页，不能代替主屏幕 Web App 的推送设置。如果没有权限弹窗，确认系统版本、启动入口，以及「设置 → 通知」中的授权。

参考：[WebKit：iOS/iPadOS 的 Web Push](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)。

### 安卓

1. 用支持 Web Push 的浏览器打开你的 cc-remote HTTPS 网址并登录。
2. 打开「⋮ → 桌面通知」，选择提醒模式并允许通知。
3. 在 Android 系统设置中，确认该浏览器及网站的通知没有被关闭。
4. 如通知延迟，检查浏览器的后台运行和电池限制；也可按浏览器提供的入口安装到主屏幕。

不同浏览器使用的推送网络可能不同。Chrome 通常使用 Google FCM，Firefox 使用 Mozilla 推送服务。Relay 和手机两端都需要能够访问所选浏览器的推送通道；某一通道不可达时，可以换用网络可达的浏览器验证。

## 第三步：选择提醒模式

| 模式 | 收到的内容 | 点击通知 |
|---|---|---|
| 关闭 | 不发送系统通知 | — |
| 通用提醒 | 仅显示任务状态或等待回答，不显示会话名称 | 打开网站首页 |
| 显示会话名称 | 显示经过截断的会话名称，不包含完整对话或工具输出 | 验证设备和会话权限后，进入对应会话 |

需要从通知直接跳转到任务时，选择「显示会话名称」。这也会让会话名称出现在手机通知中，请按自己的隐私偏好选择。

## 第四步：验证是否真的可用

1. 点击网页中的「发送测试通知」，检查手机是否显示通知。它测试的是当前设备向系统提交通知。
2. 确认设置页显示 **「后台 Push 已连接」**，而不是「当前使用页面提醒」。
3. 将网页切到后台，等待已有任务完成或需要回答，检查是否收到系统通知。
4. 如果使用会话提醒，点击通知，确认进入了正确的设备与会话。

测试按钮显示「已请求系统显示」，只表示浏览器接受了请求。它不证明后台推送已从 Relay 送达，也不证明系统展示了横幅。

## 常见问题

**电脑收到通知，手机却没有**

通知模式、权限和订阅是每个浏览器分别保存的。请在手机上重新开启；更换网址、HTTP 改为 HTTPS或清除站点数据后，也需要重新检查。

**设置页仍显示「页面提醒」**

确认服务端 Push 已开启、浏览器支持推送且已允许通知，然后刷新网页并重新选择提醒模式。该提示表示远程订阅尚未建立，不能依靠它接收关闭页面后的提醒。

**已显示后台连接，但锁屏后没有弹窗**

检查系统通知权限、专注/勿扰模式、后台限制和网络通道。还需检查登录是否过期；重新登录并开启提醒可更新订阅。服务端接受订阅不等于每次系统通知都能送达。

**能收到提醒，点击后只回到首页**

「通用提醒」按隐私设计不携带具体会话。改用「显示会话名称」后，后续通知才支持会话跳转。该功能定位到会话，不保证滚动到某一条历史消息。

**关闭页面甚至退出浏览器后也能像微信一样保证送达吗**

不能做同样的保证。Web Push 支持符合条件的后台通知，具体行为取决于浏览器、操作系统、网络和订阅有效期；强制停止、禁用后台运行或不兼容的浏览器可能阻止送达。
