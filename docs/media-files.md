# 网页中的图片、视频与本地文件

聊天中的本地文件链接和行内代码路径可以直接点击。Windows 盘符、反斜杠、
带空格或中文的路径，以及本机 `file:///` 链接都由会话所在设备读取；浏览器
不会尝试访问手机自己的同名路径，也不把本地路径交给浏览器导航。

图片可以在正文中查看并放大。视频与音频在文件面板中直接播放，支持浏览器原生
进度条、音量、全屏等功能。打开文件夹进入文件浏览面板，支持上级目录、输入路径、
复制路径、隐藏文件，以及 Windows 磁盘列表。预览面板提供打开所在文件夹和下载原文件。

视频、音频和下载通过独立的资源 WebSocket 传输，使用拉取窗口控制内存，支持 HTTP
`Range` 和 `HEAD`。无需先把整个视频转成 base64，也不受整文件预览原有的 20 MiB
限制；单个流式文件目前最多 8 GiB。中继不落盘，读取不会创建模型回合。

MP4/WebM 等能否播放取决于浏览器支持的实际编码。无法播放时可以下载原文件，
系统不会自动安装解码器、启动转码服务或改变文件。SVG、HTML 和其他文档仍使用
各自已有的安全预览方式；下载不允许页面脚本在主站执行。

媒体链接的随机 ID 不是登录凭据。每个读取请求都验证主站 Cookie、来源、设备范围、
登录会话和 Wrapper 连接代际；注销、撤销设备或关闭预览会撤销对应访问。
Code 中的显式打开仅授权该文件，Work 继续受工作目录与既有精确授权约束。
符号链接逃逸、特殊文件、网络共享路径和 Windows 数据流不作为媒体入口。

Windows 上的图片、媒体与下载支持和 HTML Remote Viewer 是两条能力边界。
`CC_REMOTE_VIEWER_CHANNEL=off` 继续禁用静态页面发布与发现；媒体读取可以单独复用
同一个认证资源连接。部署时一并更新 Wrapper、Relay 和 Web，并让主站 CSP 的
`media-src` 包含 `'self'` 与 `blob:`。官方 Caddy 模板已包含这项配置。
