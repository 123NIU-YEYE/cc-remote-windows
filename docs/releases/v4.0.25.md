# cc-remote v4.0.25

## 中文

本版修复 Graphviz SVG 预览失败，以及鸿蒙应用点击外部链接后停留在空白页面的问题。
通信协议保持 **v78**，与 v4.0.24 相同；Claude Agent SDK 保持 **0.2.157**。

### SVG 预览

- 识别 Graphviz 导出文件在 DOCTYPE 前后的完整注释，并接受合法的自闭合 SVG 根元素，避免误报「SVG 文件根元素无效」。
- 安全清理后使用 XML 序列化，避免生成 XML 不支持的 `&nbsp;` 实体；覆盖文件预览、Markdown 和 Mermaid 图片。
- 保留原有文件访问、大小限制及 SVG 清理边界，不修改用户的原始 SVG 文件。

### 鸿蒙外部链接

- 用户点击外部 HTTP(S) 链接或打开新窗口时，交给系统浏览器处理，返回后保留聊天页面和草稿。
- 同源认证页面继续在应用内打开，支持新窗口先打开空白页、再指定目标地址的流程。
- 防止同一次操作重复拉起浏览器；拉起失败时显示提示，并结束对应的新窗口处理。
- 修改仅限鸿蒙原生外壳；iOS、Android 和共享 Web 的链接处理不变。

### 升级与附件

按[部署流程](https://github.com/muggle-stack/cc-remote/blob/v4.0.25/deploy/README.md)更新 Wrapper 和 Web 客户端以获得 SVG 修复。本版没有跨协议升级；普通 Wrapper 更新仍保留独立 Claude 服务，不应为了更新而重启活跃任务。

- 六个 Relay/Wrapper 平台包、`install.sh`、`SHA256SUMS` 由 GitHub Actions 构建并提供 attestation。
- `cc-remote-android-v4.0.25.apk`：已签名，沿用原签名身份；原生版本保持 `0.1.0-preview.2`（versionCode 2），要求 Android 8.0+ 和足够新的 System WebView。
- `cc-remote-harmony-v4.0.25-unsigned.hap`：原生版本更新为 `0.1.0-preview.5`（versionCode 5）；**未签名，需使用自己的开发者及设备 Profile 签名，不能直接安装。** 不包含私人签名材料或推送服务密钥。
- `MOBILE_BUILD_INFO.json`、`MOBILE_SHA256SUMS` 记录从本 tag 受跟踪源码本地构建的移动端来源及校验值；移动端附件不属于 GitHub Actions attestation 覆盖范围。

鸿蒙用户需要更新至 preview.5 才能获得外部链接修复，已安装 preview.5 的测试用户无需重复安装。Android 原生外壳未改动，已安装 preview.2 的用户无需重装。本次不提供 iOS 或 Desktop 安装包。发布本身不会更新线上服务或已安装应用。

### 验证范围

- 完整本地检查：6,219 项 Python 测试通过、5 项预期跳过；Node 24 Web 构建、可靠性检查、Lint、Ruff、Bash 语法及 ShellCheck 通过。
- 10 项 Chromium／移动 WebKit 检查覆盖 SVG 文件预览、Markdown 和 Mermaid；提供的真实 Graphviz SVG 在桌面及移动浏览器测试中正常显示。
- 19 项鸿蒙路由、原生回调与推送测试，以及 21 项浏览器适配回归检查通过。
- Android 单元测试、Lint、构建、签名与对齐检查，以及鸿蒙 Release 编译和包内容检查通过。
- 鸿蒙 preview.5 已在测试手机覆盖安装并保留应用身份和数据，用户确认外部链接跳转正常。

上述真机确认不代表所有导航或系统进程终止场景均已验收；Android 完整真机验收仍待完成，详见各端 README。

## English

This release fixes Graphviz SVG previews and HarmonyOS external links that opened
into a blank in-app page. Wire protocol remains **v78**, the same as v4.0.24;
Claude Agent SDK remains **0.2.157**.

### Changes

- Recognize complete SVG prolog comments around a DOCTYPE and valid self-closing
  roots, preserving existing file-access and size limits.
- Serialize sanitized SVG as XML to avoid invalid `&nbsp;` entities in file
  previews, Markdown and Mermaid images. Original SVG files remain untouched.
- Open user-initiated external HTTP(S) links and popup destinations in the
  HarmonyOS system browser while retaining the mounted chat and drafts.
- Preserve same-origin authenticated navigation and blank-then-navigate popups,
  settle popup handlers, prevent duplicate launches and report launch failures.
- Keep iOS, Android and shared Web link routing unchanged.

### Upgrade and packages

Follow the [deployment procedure](https://github.com/muggle-stack/cc-remote/blob/v4.0.25/deploy/README.md)
to update Wrapper and Web for the SVG fixes. No wire-protocol migration is needed
from v4.0.24. Ordinary Wrapper updates preserve the independent Claude service
and must not restart active tasks merely to update the Wrapper.

GitHub Actions builds and attests six Relay/Wrapper bundles, the installer and
checksums. The signed Android APK (unchanged preview.2, versionCode 2) and unsigned
HarmonyOS HAP (updated preview.5, versionCode 5) are built locally from this tag.
`MOBILE_BUILD_INFO.json` and `MOBILE_SHA256SUMS` record provenance and hashes;
mobile assets are not GitHub Actions attested. The HAP requires your own
developer/device signing profile and cannot be installed directly.

HarmonyOS users need preview.5 for the external-link fix; testers already running
preview.5 need no reinstall. Android preview.2 users need no native update.
No iOS or Desktop installer is included. Publishing does not deploy services or
update installed applications.

### Validation

All local gates passed: 6,219 Python tests with 5 expected skips, Node 24 Web
build/reliability/Lint, Ruff and shell checks. Ten Chromium/mobile WebKit checks
covered SVG previews, Markdown and Mermaid, including a real Graphviz export.
Nineteen HarmonyOS routing/native callback/push tests and 21 browser-adapter
regression checks passed. Android tests, Lint, builds, signature and alignment
checks passed; the HarmonyOS Release build and package checks passed.

A signed HarmonyOS preview.5 upgrade preserved the test app's identity and data;
the operator confirmed external-link navigation on the phone. This does not
constitute acceptance of every navigation or terminated-process scenario.
Full Android device acceptance remains pending; see the native-client READMEs.
