# cc-remote v4.0.19

## 中文

v4.0.19 加快 Claude/Codex 大会话的历史加载，并修复 Claude 引导回复结束后仍显示运行的问题。
产品版本 **4.0.19**，通信协议保持 **v74**，Claude Agent SDK 保持 **0.2.157**。

- 历史分页复用已完成的摘要页、压缩边界和增量元数据，减少重复读取、扫描和翻译。
  缓存有容量上限，并根据源文件变化失效；实时运行状态仍单独更新。
- Codex 在一次历史读取中复用只读连接，合并同页细节读取，并在空闲时预取一页更早的摘要。
  保留原生用户轮次、引导输入及图片的准确对应关系。
- Claude 后台回复结束、随后接收引导输入时，可能遗留一个临时后台活动标记。
  现在由该输入对应的真实结束事件清除，实时处理和重连后的日志重放保持一致。
  无关的后台任务仍保留自己的生命周期。

### 升级

安装器管理的部署在独立终端运行：

```bash
cc-remote update --check
cc-remote update --version 4.0.19
```

`cc-remote update` 选择最新稳定版，必要时先更新配对的 Relay + Web，再更新当前设备。
其他设备各自更新，浏览器/PWA 刷新后加载新页面。

普通 Wrapper 更新保留独立 Claude 服务及其正在执行的任务。**引导回复收尾修复需要同时更新
独立 Claude 服务**；仅更新 Wrapper 不会替换旧服务的实现。请按
[Claude 服务升级流程](https://github.com/muggle-stack/cc-remote/blob/v4.0.19/docs/claude-session-service.md#first-migration-and-subsequent-deployments)
等待任务排空后升级服务，不要中断正在执行的会话来清除运行标记。

### 验证与产物

功能提交通过完整本地检查：**5971 项 Python 测试通过、4 项预期跳过**，以及
Node 24 构建、可靠性测试、lint、Ruff 和 Shell 检查。覆盖源文件追加、改写、替换、截断、
不完整记录、缓存容量、账号隔离、取消以及引导收尾重放。

同一源码已部署体验验收。14 次真实历史读取采样中，较早页首次读取为 **0.576–4.087 秒**，
重复读取为 **0.139–0.744 秒**；这是请求耗时，并非浏览器首屏时间，也不是受控的前后对照。
冷缓存仍可能需要扫描元数据，不能保证所有大会话首次加载都低于一秒。

PR #67 的 CI、代码审查和安全审查均通过。发布工作流在版本提交上重新执行 CI，
再构建并安装验证六个平台／角色包。产物包含 Linux Relay、Linux/macOS Wrapper 的
x86_64 与 arm64 包，Relay 内含 Web，并提供安装脚本、SHA-256 校验文件和发布证明。
Desktop 与实验 DSH 安装包不在本次 Release 中。

## English

v4.0.19 speeds up history loading in large Claude/Codex sessions and fixes Claude
conversations that remain marked as running after a steered reply finishes.
Product version **4.0.19**, wire protocol **v74**, Claude Agent SDK **0.2.157**.

- Reuse completed summary pages, compaction boundaries and incremental metadata
  to reduce repeated reads, scans and translation. Caches are bounded and validated
  against source changes; live activity is refreshed separately.
- Reuse read-only Codex connections within a history request, batch detail reads
  for a page and prefetch one older summary page while idle. Preserve native user
  turns, steering inputs and their image associations.
- Retire the temporary Claude background activity associated with a steered human
  reply when that reply reaches its real terminal event. Live handling and journal
  replay agree, while unrelated background tasks retain their own lifetimes.

### Upgrade

For managed installations, run `cc-remote update --check`, then
`cc-remote update --version 4.0.19` in an independent terminal. Plain
`cc-remote update` selects the latest stable release and updates the paired
Relay + Web first when needed. Update other devices separately and reload browser/PWA clients.

Ordinary Wrapper updates preserve the independent Claude service and its active
tasks. **The steering completion fix also requires upgrading that service owner.**
A Wrapper-only update does not replace its implementation. Follow the
[Claude service upgrade procedure](https://github.com/muggle-stack/cc-remote/blob/v4.0.19/docs/claude-session-service.md#first-migration-and-subsequent-deployments)
after its work drains; do not interrupt active sessions to clear a running indicator.

### Validation and assets

Feature commits passed the full local gate: **5971 Python tests passed, 4 expected
skips**, plus Node 24 build/reliability/lint, Ruff and shell checks. Coverage includes
source appends, rewrites, replacements, truncation, partial records, cache limits,
account isolation, cancellation and steered terminal replay.

The same source snapshot was deployed and accepted. In 14 real history requests,
first reads of older pages took **0.576–4.087 seconds** and repeated reads took
**0.139–0.744 seconds**. These are request timings, not browser first-paint timings
or a controlled before/after benchmark. Cold metadata scans can still take time;
sub-second initial loading is not guaranteed for every large session.

PR #67 CI and code/security reviews passed. The release workflow reruns CI on the
version commit, then builds and installation-tests all six packages. Assets include
Linux Relay and Linux/macOS Wrapper packages for x86_64 and arm64, with Web bundled
in Relay, plus the installer, SHA-256 checksums and attestations. Desktop and
experimental DSH installers are not included.
