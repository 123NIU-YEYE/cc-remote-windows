# cc-remote v4.0.13

## 中文

v4.0.13 优化 Goal 弹窗，并修复 Codex 自动续行时运行标记停留在旧回复的问题。
产品版本 **4.0.13**，通信协议保持 **v74**，Claude Agent SDK 保持 **0.2.157**。

### 本次更新

- **Goal 弹窗**：使用箭靶图标、适中的目标字号和紧凑指标，改善长目标的阅读体验。
  Codex 保留 Token 预算控制，Claude 保留检查轮次和最近一次检查结果。
- **移动端定位**：弹窗独立于经过位移的正文容器，正确使用视口坐标；弹窗内的操作
  不再触发侧栏横向拖动。
- **自动续行显示**：新一轮开始前发布准确的轮次绑定与当前状态。即使连续两轮之间
  没有进入空闲，小火花与「处理中」也会跟随新一轮，不再留在已经完成的回复上。
- **停止与重连**：保留交接期间的停止状态和准确的活动轮次；原生 CLI 或委派消息
  后续补齐用户消息身份时，不产生重复消息行。

### 升级与验证

安装器管理的部署在独立终端运行：

```bash
cc-remote update --check
cc-remote update --version 4.0.13
```

`cc-remote update` 选择最新稳定版。设备会核对配对的 Relay，必要时先更新 Relay + Web；
其他设备各自更新。用户安装预构建产物，无需运行测试或前端构建。

功能提交的完整本地检查通过：**5735 项测试通过、4 项预期跳过**，以及 Node 24 Web
构建、可靠性测试、lint、Ruff 和脚本检查。回归覆盖连续轮次交接、停止、重连、
原生消息身份补齐，以及小火花和过程标签的渲染归属；只读部署验证确认了活动 Goal
的实际绑定。本次没有发送真实模型消息，手机端动画仍需人工体验验收。

发布流程会在此版本提交上再次运行完整 CI，并为六个平台／角色组合构建、校验安装包。
产物包含 Linux Relay、Linux/macOS Wrapper 的 x86_64 与 arm64 包，Relay 内含 Web；
同时提供安装脚本、SHA-256 校验文件和发布证明。Desktop 和实验 DSH 安装包不在本次
Release 中。

## English

v4.0.13 refines Goal dialogs and fixes running indicators remaining on an older
Codex reply during automatic continuation. Product version **4.0.13**, wire
protocol **v74**, Claude Agent SDK **0.2.157**.

- Use a target icon, smaller objective text and compact metrics. Codex retains
  token-budget controls; Claude retains iteration counts and last-check details.
- Position the mobile dialog outside the transformed chat pane and prevent
  dialog gestures from opening the sidebar.
- Publish an exact binding and current state before each automatic turn's output.
  The running spark and process label follow the successor even without an idle gap.
- Preserve Stop state and reconnect ownership. Later native CLI or delegated user
  messages can refine the binding without creating duplicate rows.

### Upgrade and validation

For managed installations, run `cc-remote update --check` followed by
`cc-remote update --version 4.0.13` in an independent terminal. Plain
`cc-remote update` selects the latest stable release. Each device checks and, if
needed, updates its paired Relay + Web before updating itself; other devices
update separately. Installation uses prebuilt assets without local tests or builds.

The feature commit passed the full local gate: **5735 tests passed, 4 expected
skips**, plus Node 24 Web build/reliability/lint, Ruff and shell checks. Regressions
cover consecutive-turn handoffs, Stop, reconnects, native user-item refinement,
and rendered spark/process-label ownership. Read-only deployment checks confirmed
the active Goal's binding. No live model messages were sent; phone animation
remains a manual acceptance check.

The release workflow reruns full CI on the version commit and builds and validates
all six platform/role combinations. Assets include Linux Relay and Linux/macOS
Wrapper packages for x86_64 and arm64, with Web bundled in Relay, plus the installer,
SHA-256 checksums and release attestations. Desktop and experimental DSH installers
are not included.
