# cc-remote v4.0.20

## 中文

v4.0.20 新增 Android 与鸿蒙客户端预览版、可选的鸿蒙完成通知，并修复 Codex
提交代码后因原有未跟踪文件触发的检查点误报。
产品版本 **4.0.20**，通信协议保持 **v74**，Claude Agent SDK 保持 **0.2.157**。

- Android WebView 与鸿蒙 ArkWeb 客户端直接打开聊天，无额外地址栏；支持选择服务器、
  附件选择和应用内网页浏览，返回聊天时保留会话与草稿。
- 鸿蒙可通过 Huawei Push Kit 接收完成、失败或中断通知。默认关闭，支持通用提醒和
  显示会话名称两种模式；需要自行配置华为应用、签名能力及 Relay 服务账号。
  现有 Web/PWA 的 Web Push 保持不变。
- 修复通知适配器加载失败及开通响应丢失时的状态处理：清理不确定的订阅和原生令牌，
  清理失败会明确提示，并在重试前继续清理。
- Codex 轮次内正常向前提交代码时，允许原先已存在且内容、权限未变的未跟踪文件保留，
  不再因此误报文件检查点不可用。新增或变更的遗留文件、未提交暂存仍按安全边界处理。
  这类已提交轮次仍仅支持对话回滚，不会替用户撤销 Git 提交，也不会改写旧的失败记录。

### 下载与安装

| 产物 | 使用方式 |
| --- | --- |
| `cc-remote-android-v4.0.20.apk` | 已签名，可在 Android 8.0+ 安装，需较新的 System WebView。卓易通兼容性和流畅度取决于其运行环境。 |
| `cc-remote-harmony-v4.0.20-unsigned.hap` | 鸿蒙原生构建产物，**未签名，不能直接点按安装**。需用自己的开发者账号及设备 Profile 签名；个人设备绑定的签名包不公开分发。 |
| `MOBILE_SHA256SUMS` / `MOBILE_BUILD_INFO.json` | 移动端校验值、源码及构建信息。移动端包由维护者本地构建，与 CI 构建的服务端产物分开记录。 |

两端原生壳版本均为 **0.1.0-preview.2（versionCode 2）**，独立于 Relay/Web 产品版本。
安装后填入自己的 HTTPS Relay 地址，使用原有登录方式。原生壳变化需要更新安装包；
日常 Web 功能更新通常只需刷新页面。本次不含 iOS 或 Desktop 安装包。

详见 [Android 安装说明](https://github.com/muggle-stack/cc-remote/blob/v4.0.20/android/README.md)
及 [鸿蒙签名、安装与 Push Kit 配置](https://github.com/muggle-stack/cc-remote/blob/v4.0.20/harmony/README.md)。

### 升级与验证范围

安装器管理的部署在独立终端运行：

```bash
cc-remote update --check
cc-remote update --version 4.0.20
```

更新 Relay + Web 和各设备 Wrapper；普通 Wrapper 更新保留独立 Claude 服务与活动任务。
本次发布不会自动更新现有部署或手机安装包。

完整本地检查通过：**5992 项 Python 测试通过、4 项预期跳过**，以及 Node 24
构建、可靠性测试、lint、Ruff 和 Shell 检查。移动端另有原生构建、单元测试及适配器
浏览器检查。发布工作流重新执行 CI，并构建、安装验证六个平台／角色包；服务端包、
安装脚本及 `SHA256SUMS` 提供 GitHub 发布证明，移动端包不冒称 CI 构建或证明。

移动端仍为预览版：Android 真机完整验收尚未完成；鸿蒙已验证实际安装、登录及锁屏
测试通知接收和点击回到应用。工作事项通知分类尚待批准，进程被系统终止后的投递、
冷／热启动精确会话跳转等仍需进一步真机验收。后续报告的鸿蒙侧栏卡顿暂未调整。
测试通知成功不代表生产通知已全面验收。Android 原生推送、相机／麦克风、下载管理和
应用内自动更新不在当前范围内。

## English

v4.0.20 introduces preview Android and native HarmonyOS clients, optional Huawei
Push Kit completion notifications, and a Codex checkpoint correction. Product
version **4.0.20**, wire protocol **v74**, Claude Agent SDK **0.2.157**.

- Open chat without an extra address bar, choose an HTTPS server, attach files,
  and browse links in-app while retaining the chat and draft.
- HarmonyOS supports opt-in generic or named-session completion notifications.
  Configure your Huawei application, signing entitlement and Relay service
  account separately. Existing Web/PWA Web Push behavior is preserved.
- Notification adapter failures and ambiguous subscription responses now settle
  explicitly, revoke uncertain native bindings and require pending cleanup
  before retrying.
- A normal forward Git commit no longer triggers a false checkpoint warning
  solely because unchanged pre-existing untracked files remain. New/modified
  leftovers and staged changes still fail closed. Such committed turns support
  conversation-only rollback; cc-remote does not undo Git commits or rewrite
  previously recorded failures.

### Mobile assets

- **`cc-remote-android-v4.0.20.apk`**: signed, installable on Android 8.0+ with
  a recent System WebView. Compatibility-layer behavior is environment-dependent.
- **`cc-remote-harmony-v4.0.20-unsigned.hap`**: native HarmonyOS build artifact,
  **not directly installable**. Sign it with your own developer/device profile.
  Private device-bound signed packages are not publicly distributed.
- **`MOBILE_SHA256SUMS` and `MOBILE_BUILD_INFO.json`**: checksums and provenance
  for maintainer-built mobile artifacts, separate from the CI-built core assets.

Both native shells remain **0.1.0-preview.2 (versionCode 2)**, independently of
the hosted Relay/Web version. See the [Android guide](https://github.com/muggle-stack/cc-remote/blob/v4.0.20/android/README.md)
and [HarmonyOS signing and push guide](https://github.com/muggle-stack/cc-remote/blob/v4.0.20/harmony/README.md).
No iOS or Desktop installer is included.

### Upgrade and validation

For managed installations, run `cc-remote update --check`, then
`cc-remote update --version 4.0.20` in an independent terminal. Update Relay/Web
and each Wrapper. Ordinary Wrapper updates preserve the separate Claude service
and active tasks. Publishing does not itself update running services or phones.

The full local gate passed: **5992 Python tests, 4 expected skips**, Node 24
build/reliability/lint, Ruff and shell checks. Mobile builds, unit tests and
adapter browser checks are also available. Release CI reruns source checks and
builds and installation-tests all six core packages. Core bundles, installer and
`SHA256SUMS` carry GitHub attestations; local mobile artifacts are identified
separately and are not claimed to have CI provenance.

Mobile clients are previews. Full Android device acceptance remains pending.
HarmonyOS installation/login and a locked-phone test notification with return to
the app were confirmed. WORK category approval, process-terminated delivery and
exact cold/warm session navigation remain pending; a successful test notification
is not complete production push acceptance. A later sidebar-stutter report is
not addressed in this release. Android native push, camera/microphone, download
management and native auto-update remain outside this preview.
