# cc-remote v4.0.22

## 中文

本版修复 Linux 升级时共享 Codex daemon 的生命周期问题，以及扩展名不正确的图片无法预览的问题。通信协议保持 **v76**，Claude Agent SDK 保持 **0.2.157**。

### 修复

- Linux systemd Wrapper 启动的 Codex 原生命令改由独立的用户服务执行，避免 Wrapper 停止时一起清理共享 daemon。保留每个账号的环境、工作目录与资源限制；已有可连接的 daemon 继续复用，不自动重启或迁移。
- 升级前要求运行中的 Wrapper 确认暂停新的 Codex 生命周期命令，并保持到停止完成。进行中的命令、进程代际变化、无法核实的服务状态都会拒绝升级；停止意图写入恢复记录，丢失响应不会重新放开启动窗口。
- 对已允许的位图文件按实际内容识别 PNG、JPEG、GIF、WebP、AVIF。JPEG 被命名为 `.png` 等情况可正常预览，覆盖文件面板、Artifacts 和 Markdown 图片。不改写原文件，保留权限、体积和解码限制，不放宽 SVG、HTML 或 PDF 校验。

### Linux 首次升级须知

**正在运行的旧 Linux systemd Wrapper 无法确认新的启动屏障，因此首次升级会安全拒绝，服务保持原样。** 请等待原生任务结束，在维护窗口停止旧 Wrapper 后再重试安装器。新安装或已停止的服务不需要这一步。不要在活跃旧服务上绕过检查。

如果旧共享 daemon 仍属于 Wrapper 的 cgroup，先等待对应账号的任务结束，再从独立登录终端使用该账号的日常 Codex CLI 执行官方 `app-server daemon restart`，核实 daemon 已在 Wrapper cgroup 外。不要为了升级终止正在运行的任务或移动进程树。

新的隔离启动路径需要服务用户的 systemd manager 运行；无人值守安装需配置相应的 linger。完整步骤见 [Codex 共享控制面验收](../../deploy/README.md#codex-code-shared-control-plane-acceptance)。macOS 和非 systemd 启动路径不受这项维护要求影响。普通 Wrapper 升级仍不重启独立 Claude 服务。

### 安装包

- 六个 Relay/Wrapper 平台包、`install.sh`、`SHA256SUMS`：由 GitHub Release 工作流构建并提供 attestation。
- `cc-remote-android-v4.0.22.apk`：使用原签名身份的 Android 安装包，原生版本保持 `0.1.0-preview.2`（versionCode 2）。要求 Android 8.0+ 和足够新的 System WebView。
- `cc-remote-harmony-v4.0.22-unsigned.hap`：鸿蒙原生版本保持 `0.1.0-preview.4`（versionCode 4）。**未签名，需使用自己的开发者及设备 Profile 签名，不能直接安装。** 不包含私人签名材料或推送服务密钥。
- `MOBILE_BUILD_INFO.json`、`MOBILE_SHA256SUMS`：记录移动端构建来源和校验值。两个移动端包从本次 tag 的受跟踪源码在维护者本地构建，不属于 GitHub Actions attestation 覆盖范围。

本版没有修改移动端原生外壳；已安装上述原生版本的用户无需为本次修复重装手机应用。Android 完整真机验收和鸿蒙所有进程终止场景的推送验收仍有缺口，详见各端 README。本次不提供 iOS 或 Desktop 安装包。

### 验证

- 完整本地检查：6,122 项 Python 测试通过，5 项预期跳过；Node 24 Web 构建、可靠性测试、Lint、Ruff、Shell 检查通过。
- 离线回归覆盖检查后新启动的竞态、忙碌与旧版服务、进程代际变化、响应丢失、停止超时和恢复记录。
- 独立 Linux 探针验证真实 Unix socket 身份检查和启动互斥；停止命令使用替身，没有停止生产服务。systemd 隔离验证使用可派生进程的测试程序，没有调用模型。
- Android 单元测试、Lint、Release 构建及签名校验通过；鸿蒙 Release 构建通过。

发布不会更新线上服务或手机安装。部署验收与发布校验是独立步骤。

## English

This release protects shared Codex daemon lifetime during Linux Wrapper upgrades
and fixes previews of raster images with misleading extensions. Wire protocol
remains **v76**, and Claude Agent SDK remains **0.2.157**.

### Fixes

- Run native Codex lifecycle commands through an isolated systemd user service,
  outside the Wrapper cgroup. Preserve per-account environment, working directory
  and resource limits; reuse reachable daemons without automatically restarting
  or relocating them.
- Hold a process-bound launch barrier throughout upgrade inspection and stop.
  In-flight commands, process-generation changes and unverifiable service state
  reject activation. Persist stop intent for recovery; lost responses cannot
  reopen the launch window after stop has been committed.
- Identify allowed PNG, JPEG, GIF, WebP and AVIF files from their contents in file
  previews, Artifacts and Markdown images. Keep source bytes, authorization, size
  and decoder limits unchanged; SVG, HTML and PDF validation is not relaxed.

### First Linux upgrade

**A running legacy Linux systemd Wrapper cannot acknowledge the new barrier, so
its first upgrade is refused without stopping the service.** Wait for native
tasks to finish, stop the old Wrapper during a maintenance window, then retry
the installer. Fresh installations and already-stopped services do not require
this step. Do not bypass this check on a live legacy service.

If an existing shared daemon remains in the Wrapper cgroup, wait for that
account's tasks to finish, run the official `app-server daemon restart` using
the account's daily CLI from an independent login terminal, and verify the
daemon is outside the Wrapper cgroup. Never kill active work or move a live
process tree to pass the check. The isolated launcher requires a running systemd
user manager; configure lingering for unattended use. See the
[shared-control-plane procedure](../../deploy/README.md#codex-code-shared-control-plane-acceptance).
macOS and non-systemd paths do not have this maintenance requirement. Ordinary
Wrapper upgrades still preserve the independent Claude service.

### Packages and validation

The six Relay/Wrapper bundles, installer and checksums are built and attested by
GitHub Actions. The signed Android APK (native preview.2, versionCode 2) and
unsigned HarmonyOS HAP (native preview.4, versionCode 4) are built locally from
this tagged source; `MOBILE_BUILD_INFO.json` and `MOBILE_SHA256SUMS` record their
provenance and hashes. Mobile assets are not covered by GitHub Actions
attestation. The HAP needs your own developer/device signing profile and contains
no private signing material or Push service key. Native shell code is unchanged;
users already on these native versions need no phone reinstall for this fix.
Full Android device acceptance and all terminated-process Harmony push scenarios
remain pending. No iOS or Desktop installer is included.

All local gates passed: 6,122 Python tests with 5 expected skips, Node 24 Web
build/reliability/Lint, Ruff and shell checks. Offline tests cover launch/stop
races, legacy and busy services, generation changes, lost responses, stop timeouts
and recovery intent. Isolated Linux probes exercised real Unix socket identity
and mutual exclusion with service stop stubbed; systemd isolation used a forking
test program without model calls. Android tests, Lint, Release build and signature
verification passed; the HarmonyOS Release build passed.

Publishing does not deploy services or update installed applications.
