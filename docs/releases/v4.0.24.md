# cc-remote v4.0.24

## 中文

本版修复 Claude MCP 询问工具丢失及工具刷新恢复问题，并允许收起待回答问题、先阅读对话。
通信协议保持 **v78**，与 v4.0.23 相同；Claude Agent SDK 保持 **0.2.157**。

### 询问与工具恢复

- Claude 原生 `AskUserQuestion` 与 MCP `ask_user` 均可收起为输入区分割线上方的「继续回答」条，主聊天及侧边聊天都支持。再次打开时保留当前题目、已选答案、自定义文字和滚动位置。
- 收起只改变界面，不提交答案、不取消问题，也不让 Claude 继续执行。原有等待、超时和服务端关闭规则保持不变；收起再打开也不会重复提交答案。
- 点击或编辑单选题的自定义答案时，取消之前选中的卡片；重新选择卡片时清除自定义文字。Tab／Shift+Tab 和程序聚焦不会改变答案，多选补充文字与输入法组合输入保持可用。
- 单题和批量 `ask_user` 使用 Claude 可识别的对象输入结构，由处理函数校验互斥形式，修复工具可能从 MCP 目录中消失的问题。
- 工具刷新被打断后可恢复询问和跨会话消息入口，无需替换原生进程。消息功能停用后安全清理残留路由；询问路由被用户关闭时不会自动启用它，也不会阻止独立消息路由刷新。

详见[询问工具](https://github.com/muggle-stack/cc-remote/blob/v4.0.24/docs/user-questions.md)及[会话通信](https://github.com/muggle-stack/cc-remote/blob/v4.0.24/docs/session-messages.md)。

### 升级与附件

按[部署流程](https://github.com/muggle-stack/cc-remote/blob/v4.0.24/deploy/README.md)更新并刷新 Web 客户端。本版没有跨协议升级；普通 Wrapper 更新仍保留独立 Claude 服务，不应为了更新而重启活跃任务。

- 六个 Relay/Wrapper 平台包、`install.sh`、`SHA256SUMS` 由 GitHub Actions 构建并提供 attestation。
- `cc-remote-android-v4.0.24.apk`：已签名，沿用原签名身份；原生版本保持 `0.1.0-preview.2`（versionCode 2），要求 Android 8.0+ 和足够新的 System WebView。
- `cc-remote-harmony-v4.0.24-unsigned.hap`：原生版本保持 `0.1.0-preview.4`（versionCode 4）；**未签名，需使用自己的开发者及设备 Profile 签名，不能直接安装。** 不包含私人签名材料或推送服务密钥。
- `MOBILE_BUILD_INFO.json`、`MOBILE_SHA256SUMS` 记录从本 tag 受跟踪源码本地构建的移动端来源及校验值；移动端附件不属于 GitHub Actions attestation 覆盖范围。

移动端原生代码未改动，已安装上述版本的用户无需重装手机应用。本次不提供 iOS 或 Desktop 安装包。发布本身不会更新线上服务或已安装应用。

## English

This release restores Claude MCP question tools and lets users collapse a pending
question to read the conversation before answering. Wire protocol remains **v78**,
the same as v4.0.23; Claude Agent SDK remains **0.2.157**.

### Questions and tool recovery

- Native `AskUserQuestion` and MCP `ask_user` can collapse into a resume bar above
  the composer divider in main and side chats. Reopening restores the question
  page, choices, custom answer and scroll position.
- Collapse changes presentation only: it sends no answer, cancellation or turn
  command. Claude keeps waiting, existing deadlines and server closure still
  apply, and reopening cannot resubmit an answer already being sent.
- Clicking or editing a custom single-choice answer clears the previous choice;
  selecting a card clears the custom answer. Tab traversal and programmatic focus
  preserve choices. Multi-select supplemental text and IME input remain supported.
- A compatible object schema advertises single and batched `ask_user` inputs,
  with exclusive-form validation in the handler, preventing catalog rejection.
- Interrupted ask/message tool refreshes recover without replacing the native
  process. Messaging opt-out retires pending routes safely; a user-disabled ask
  route stays disabled and does not block an independent message route refresh.

See [user questions](https://github.com/muggle-stack/cc-remote/blob/v4.0.24/docs/user-questions.md)
and [session messaging](https://github.com/muggle-stack/cc-remote/blob/v4.0.24/docs/session-messages.md).

### Upgrade, packages and validation

Follow the [deployment procedure](https://github.com/muggle-stack/cc-remote/blob/v4.0.24/deploy/README.md)
and refresh Web clients. There is no wire-protocol migration from v4.0.23.
Ordinary Wrapper updates preserve the independent Claude service and must not
restart active tasks merely to update tools.

GitHub Actions builds and attests six Relay/Wrapper bundles, the installer and
checksums. The signed Android APK (unchanged preview.2, versionCode 2) and unsigned
HarmonyOS HAP (unchanged preview.4, versionCode 4) are built locally from this tag.
`MOBILE_BUILD_INFO.json` and `MOBILE_SHA256SUMS` record provenance and hashes;
mobile assets are not GitHub Actions attested. The HAP requires your own
developer/device signing profile. Existing users need no phone reinstall.
No iOS or Desktop installer is included. Publishing does not deploy services or
update installed applications.

All local gates passed: 6,205 Python tests with 5 expected skips, Node 24 Web
build/reliability/Lint, Ruff and shell checks. Fourteen Chromium/mobile WebKit
checks passed using a mocked Relay; mobile WebKit scrolling is programmatic.
Isolated Claude CLI probes verified recovery while retaining the native PID,
without model queries. Android tests, Lint, builds, signature and alignment
checks passed; the HarmonyOS Release build and package checks passed.

Physical-phone and live-model acceptance of question collapse remains pending.
Full Android device acceptance and all terminated-process Harmony push scenarios
also remain pending; see the native-client READMEs.
