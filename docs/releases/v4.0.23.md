# cc-remote v4.0.23

## 中文

本版新增 Claude/Codex 跨会话通信，并统一原生工具和 MCP 的分页询问体验。
通信协议从 **v76 升级至 v78**，Claude Agent SDK 保持 **0.2.157**。

### 会话通信

- 提供可选的 `list_sessions`、`send_message`、`message_status` MCP 工具，支持同一设备上已配置的 Claude/Codex Code 账号之间通信；调用方绑定真实账号及会话，不修改模型凭据。原生 Codex App 消息入口继续支持。
- 为忙碌目标保存持久消息队列，等待其可接收输入；保留去重记录，遇到提交结果不确定时不会自动重发。回执表示输入接收状态，不等于任务已经完成；回信由目标会话主动发送。
- 旧 Claude 常驻进程在安全的空闲时机刷新消息工具，无需重启原生进程；恢复时保留刷新状态和已接收消息。
- 点击消息来源或目标可直接打开对应会话，支持统一入口的跨引擎、跨账号跳转，保留原会话草稿。

通信默认关闭，需要显式启用 `CC_REMOTE_SESSION_MESSAGES=1`；Codex 账号还需注册相应 MCP。仅限当前设备的 Code 会话，不包含 Work 或私有侧边聊天。目标会话沿用自身权限，发送方的沙箱不会随消息传递。详见[会话通信](https://github.com/muggle-stack/cc-remote/blob/v4.0.23/docs/session-messages.md)。

### 询问体验

- Claude 原生 `AskUserQuestion` 与 cc-remote MCP `ask_user` 共用居中表单，一次可处理 1–4 个问题。
- 圆角上一题/下一题按钮保留各页选择、自定义答案和滚动位置，最后统一提交；单选、多选通过卡片配色表示选中状态。
- 切换会话或同页面重连可保留填写进度，待处理问题可重新呈现；TUI 同步支持批量回答。

旧原生进程可能暂时缓存旧 MCP 询问工具结构，待正常工具发现或下次启动后更新；原生询问回调可直接使用新 Wrapper 的表单。详见[询问工具](https://github.com/muggle-stack/cc-remote/blob/v4.0.23/docs/user-questions.md)。

### 升级与安装包

**Web、Relay、Wrapper 必须协调升级，v76 与 v78 不能混用。** 按[部署流程](https://github.com/muggle-stack/cc-remote/blob/v4.0.23/deploy/README.md)执行协议切换，完成后刷新客户端。普通 Wrapper 升级仍保留独立 Claude 服务，不应为了更新而重启活跃原生任务。

- 六个 Relay/Wrapper 平台包、`install.sh`、`SHA256SUMS`：由 GitHub Actions 构建并提供 attestation。
- `cc-remote-android-v4.0.23.apk`：使用原签名身份，原生版本保持 `0.1.0-preview.2`（versionCode 2），要求 Android 8.0+ 与足够新的 System WebView。
- `cc-remote-harmony-v4.0.23-unsigned.hap`：原生版本保持 `0.1.0-preview.4`（versionCode 4）；**未签名，需使用自己的开发者及设备 Profile 签名，不能直接安装。** 不包含私人签名材料或推送服务密钥。
- `MOBILE_BUILD_INFO.json`、`MOBILE_SHA256SUMS`：记录从本 tag 受跟踪源码本地构建的移动端来源及校验值；移动端包不属于 GitHub Actions attestation 覆盖范围。

移动端原生外壳没有变化，已安装上述原生版本的用户无需为本版重装手机应用。Android 完整真机验收和鸿蒙所有进程终止场景的推送验收仍有缺口，详见各端 README。本次不提供 iOS 或 Desktop 安装包。发布本身不会更新现有服务或手机安装。

## English

This release adds Claude/Codex session messaging and a shared paginated question
form for native Claude tools and MCP. Wire protocol advances from **v76 to v78**;
Claude Agent SDK remains **0.2.157**.

### Session messaging and questions

- Opt-in `list_sessions`, `send_message` and `message_status` tools route between
  configured Code accounts on the same device. Caller identity is account/session
  bound; model credentials are unchanged. The native Codex App entry remains
  supported. Work, private side chats and other devices are excluded.
- A durable, deduplicated inbox retains messages for busy recipients. Uncertain
  native submissions are not automatically replayed. Receipts describe input
  acceptance, not task completion; replies are explicit messages from the target.
  Targets retain their own permissions rather than inheriting the sender's sandbox.
- Persistent Claude workers refresh message tools at safe idle boundaries without
  restarting native processes. Message links open the exact conversation and
  preserve drafts across engine/account switches.
- Native `AskUserQuestion` and MCP `ask_user` share a centered 1–4 question form.
  Rounded Previous/Next buttons preserve each page's choices, custom answers and
  scroll position; answers submit atomically. Selected cards use theme colors,
  with equivalent batch handling in the TUI.

Messaging is disabled by default: enable `CC_REMOTE_SESSION_MESSAGES=1` and
register the MCP explicitly for each Codex account. Existing Claude processes
may cache an older MCP question schema until ordinary tool discovery or restart;
native question callbacks use the new Wrapper immediately. See
[session messaging](https://github.com/muggle-stack/cc-remote/blob/v4.0.23/docs/session-messages.md)
and [user questions](https://github.com/muggle-stack/cc-remote/blob/v4.0.23/docs/user-questions.md).

### Upgrade, packages and validation

**Upgrade Web, Relay and Wrapper together; v76 and v78 are incompatible.** Follow
the [deployment procedure](https://github.com/muggle-stack/cc-remote/blob/v4.0.23/deploy/README.md)
and refresh clients afterward. Ordinary Wrapper upgrades preserve the independent
Claude service and must not restart active native tasks merely to update tools.

The six Relay/Wrapper bundles, installer and checksums are built and attested by
GitHub Actions. The signed Android APK (native preview.2, versionCode 2) and
unsigned HarmonyOS HAP (native preview.4, versionCode 4) are built locally from
this tagged source. `MOBILE_BUILD_INFO.json` and `MOBILE_SHA256SUMS` record their
provenance and hashes; these mobile assets are not GitHub Actions attested.
The HAP requires your own developer/device signing profile. Native shell code is
unchanged, so users on these native versions need no phone reinstall. Full Android
device acceptance and all terminated-process Harmony push scenarios remain
pending. No iOS or Desktop installer is included.

All local gates passed: 6,181 Python tests with 5 expected skips, Node 24 Web
build/reliability/Lint, Ruff and shell checks. Ten Chromium/WebKit navigation and
draft-preservation checks passed. Local Claude CLI probes verified tool refresh
and controller replacement without model calls. Maintainer live tests confirmed
cross-account Claude messaging, receipts, sequential MCP questions and a native
three-question batch. Android tests, Lint, builds, signature and alignment checks
passed; the HarmonyOS Release build and package checks passed.

Publishing does not deploy services or update installed applications.
