# cc-remote v4.0.28

## 中文

本版修复交付文件未进入 Artifacts 的问题，并让 Codex 原生协作代理出现在后台任务入口。
通信协议保持 **v78**，与 v4.0.27 相同；Claude Agent SDK 保持 **0.2.157**。

### Artifacts 文件收录

- 识别助手正文中的明确本地文件路径，以及先给目录、再用列表或表格列出文件名的交付格式，覆盖实时消息与历史记录。
- 兼容目录末尾没有斜线、明确标注的相对目录，以及省略两侧竖线、混合边界和短行的 Markdown 表格。
- 表格仅从唯一的文件名／路径列收录文件，避免把说明列里的代码引用误当作交付文件。
- 保留数量限制、会话归属及现有文件预览权限；不扫描目录，不扩大文件访问范围。

### Codex 后台任务

- 将原生 Codex 子代理与 MCP 后台任务一起显示，读取当前账号的原生目录和运行记录，不发起额外模型调用。
- 按子代理自己的轮次跟踪完成状态，兼容 `task_complete` 和 `task_completed`；父会话或启动工具完成不会提前清除仍在工作的代理。
- 原生代理与 MCP 来源独立刷新；某个来源失败时保留其已知状态，让其他正常来源继续更新。
- 局部刷新保留其他驻留会话的状态；数量限制按父会话隔离，避免一个会话的历史影响其他会话。
- 保留重连同步、源文件归属校验和有界增量读取；数据不可读时不会猜测任务已经完成。

### 升级与附件

按[部署流程](https://github.com/muggle-stack/cc-remote/blob/v4.0.28/deploy/README.md)更新服务并重新加载 Web 客户端。本版没有跨协议升级；普通 Wrapper 更新仍保留独立 Claude 服务。

- 六个 Relay/Wrapper 平台包、`install.sh`、`SHA256SUMS` 由 GitHub Actions 构建并提供 attestation。
- Android／鸿蒙源码与 v4.0.27 完全相同，沿用该版本已发布包的原始字节：Android 为已签名 preview.2（versionCode 2）；鸿蒙为未签名 preview.5（versionCode 5）。
- `MOBILE_BUILD_INFO.json` 记录原始构建来源和本次复用信息，`MOBILE_SHA256SUMS` 提供校验值。移动端附件不属于 GitHub Actions attestation 覆盖范围。
- 鸿蒙 HAP 需要使用自己的开发者及设备 Profile 签名，不能直接安装。已有 Android preview.2／鸿蒙 preview.5 用户无需重装原生应用。

本次不提供 iOS 或 Desktop 安装包。发布本身不会更新线上服务或已安装应用。

### 验证范围

功能提交通过完整本地检查：6,308 项 Python 测试通过、5 项预期跳过；Node 24 Web 构建、可靠性检查、Lint、Ruff、Bash 语法及 ShellCheck 通过。PR #76 最新提交的代码审查和安全审查完成，无新增问题。

原始实现已验证受影响 Claude 会话的三张 PNG 能被收录，并通过只读探针验证原生代理活动及其真实完成后的移除。后续审查修复覆盖目录／表格格式、来源异常、局部刷新、旧版完成标记与父会话数量隔离；这些后续修复尚未重新部署验收。本次未重新执行完整文件预览点击流程或移动端真机流程，也未发送模型测试消息。

## English

This release restores delivered files in Artifacts and shows native Codex agents
in the background task control. Wire protocol remains **v78**, the same as
v4.0.27; Claude Agent SDK remains **0.2.157**.

### Changes

- Discover explicit local file paths and directory-introduced filenames in
  assistant lists and tables, for both live messages and history. Support
  slashless directory introductions and Markdown tables with optional outer
  pipes, mixed boundaries and short rows.
- Read only the uniquely identified filename/path table column. Keep discovery
  bounded, preserve existing file-preview permissions and do not crawl directories.
- Merge native Codex child activity with MCP background tasks using account-local
  native records. Track each child's own turn, including legacy completion markers;
  completion of a parent or spawn tool does not finish the child.
- Refresh sources independently, retain known state during unavailable reads or
  partial refreshes, and scope inventory limits per parent session. Preserve
  reconnect synchronization and bounded incremental reads without model calls.

### Upgrade and packages

Follow the [deployment procedure](https://github.com/muggle-stack/cc-remote/blob/v4.0.28/deploy/README.md)
and reload the Web client. No wire-protocol migration is needed from v4.0.27.
Ordinary Wrapper upgrades preserve the independent Claude service.

GitHub Actions builds and attests six Relay/Wrapper bundles, the installer and
checksums. Android and HarmonyOS sources are unchanged from v4.0.27, so their
published binaries are reused byte-for-byte: signed Android preview.2 and unsigned
HarmonyOS preview.5. `MOBILE_BUILD_INFO.json` preserves their original build
provenance and records this reuse; `MOBILE_SHA256SUMS` provides checksums. Mobile
assets are not GitHub Actions attested. The HAP requires your own developer/device
signing profile. Existing users need no native reinstall.

No iOS or Desktop installer is included. Publishing does not deploy services or
update installed applications.

### Validation

The feature commit passed the full local gate: 6,308 Python tests with 5 expected
skips, Node 24 Web build/reliability/Lint, Ruff and shell checks. Code and security
reviews completed on PR #76's latest feature commit without new findings.

The initial implementation recovered the affected Claude session's three PNG
entries and passed a read-only native-agent activity/terminal probe. Follow-up
review fixes have regression coverage but have not been redeployed for acceptance.
Full click-to-preview and native mobile device flows were not rerun; no model
prompts were sent.
