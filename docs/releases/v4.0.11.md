# cc-remote v4.0.11

## 中文

v4.0.11 新增可选的 Codex 异步后台任务，修复 Claude BTW 侧聊历史恢复及安装兼容性。
产品版本 **4.0.11**，通信协议保持 **v74**，Claude Agent SDK 保持 **0.2.157**。

### 本次更新

- **异步任务 MCP**：提供 `task_start`、`task_status`、`task_result`、`task_cancel`。
  命令、测试和外部代理经共享的官方 Codex daemon 执行，结果回到原账号、原会话。
  外部任务的命令需要等待实际完成并返回结果；仅返回任务 ID 不代表工作已完成。
- **后台任务显示**：输入框上方可展开查看任务；收到结果后标识
  “Codex 收到后台消息，继续处理”。刷新或重连后恢复任务状态及消息顺序，
  后台任务不会单独将主对话标为运行或未读。
- **执行与回调可靠性**：提交前重新检查剩余时限，过期后不启动命令；正确识别原生超时。
  回调被接收后继续核对对应轮次，正常结束才记为送达；失败、拒绝和无法确认的结果保留供查询。
  不自动重跑执行结果不明的命令，也不重复发送可能已被接收的回调。
- **升级后刷新**：`cc-remote tasks refresh` 可刷新已启用的任务 MCP，并用现有会话的
  只读工具调用验证连接，无需重启 daemon 或调用模型。
- **Claude BTW 修复**：等待历史恢复完成后再显示并定位到底部，补齐恢复后的完成标记，
  保留后台继续处理消息顺序。
- **安装兼容性**：修复 macOS Bash 3.2 安装和 Supervisor 严格变量检查下的预检问题。
  中英文文档推荐使用 Release 安装，并通过 `cc-remote update` 更新。

### 使用与兼容性

任务 MCP 需显式启用，要求 **Codex 0.159.2 或更新版本**及已运行的共享 daemon。
升级不会自动启用 MCP。按账号配置方法与刷新命令见
[异步任务指南](https://github.com/muggle-stack/cc-remote/blob/v4.0.11/docs/async-tasks.md)。
任务使用账号配置的命令权限，不继承会话临时权限覆盖。

部分严格的 Responses 供应商仍可能拒绝 Codex 0.159.2 生成的无 call ID 回调；
本版会显示回调失败并保留结果，不改变上游请求格式或账号凭据。
App／CLI 的原生显示由官方客户端决定，尚未完成全部跨客户端组合的实机验收。

### 升级

安装器管理的部署在独立终端运行：

```bash
cc-remote update --check
cc-remote update --version 4.0.11
```

`cc-remote update` 会选择最新稳定版。设备先核对配对的 Relay，必要时先更新 Relay + Web；
Relay 已为目标兼容版本时只更新本机，其他设备各自更新。
用户安装预构建产物，不需要运行 CI、pytest 或前端构建。

发布产物包含 Linux Relay、Linux/macOS Wrapper 的 x86_64 与 arm64 包，Relay 内含 Web。
Desktop 和实验 DSH 安装包不在本次 Release 中。

## English

v4.0.11 adds optional asynchronous Codex tasks and fixes Claude BTW history
restoration and installer compatibility. Product version **4.0.11**, wire protocol
**v74**, Claude Agent SDK **0.2.157**.

- Start, inspect, retrieve and cancel commands or external-agent jobs through an
  account's shared official Codex daemon. Results return to the originating thread.
  A submitted command must wait for the actual job and print its result; returning
  a job ID only reports that launch as complete.
- Show background activity above the composer and label resumed processing.
  Reconnects restore task state and continuation order without treating background
  activity as main-conversation execution or unread completion.
- Recheck deadlines immediately before command submission and classify native
  timeouts correctly. Confirm the exact callback turn's successful completion before
  marking delivery successful. Retain failed or uncertain results and never
  automatically repeat commands or callbacks whose submission may have succeeded.
- Refresh an enabled MCP after upgrades with `cc-remote tasks refresh`, optionally
  verifying an existing thread's read-only tool call without restarting its daemon
  or invoking a model.
- Restore Claude BTW history before displaying it at the bottom, retain completion
  markers and preserve background continuation order.
- Fix macOS Bash 3.2 installation and Supervisor preflight under strict variable
  checks. Recommend Release installations and one-command updates in both languages.

### Compatibility and upgrade

The task MCP is opt-in and requires **Codex 0.159.2+** with an existing shared daemon.
Upgrading does not enable it automatically. See the
[task guide](https://github.com/muggle-stack/cc-remote/blob/v4.0.11/docs/async-tasks.md)
for account configuration and refresh commands. Tasks use account command
permissions, not temporary per-thread overrides.

Some strict Responses providers still reject Codex 0.159.2's call-ID-less callback;
this release reports failure and retains output rather than rewriting native
requests or account credentials. Native App/CLI presentation remains client-owned;
full cross-client live acceptance is not claimed.

For managed installations, run `cc-remote update --check` followed by
`cc-remote update --version 4.0.11` in an independent terminal. Plain
`cc-remote update` selects the latest stable release. Each device verifies and, if
needed, upgrades its paired Relay + Web before updating itself. Other devices
update separately. Installation uses prebuilt assets without CI, pytest or a Web
build on the user's machine.

Assets include Linux Relay and Linux/macOS Wrapper packages for x86_64 and arm64,
with Web bundled in Relay. Desktop and experimental DSH installers are not included.
