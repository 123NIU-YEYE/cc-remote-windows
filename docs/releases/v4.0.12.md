# cc-remote v4.0.12

## 中文

v4.0.12 修复 Codex Goal 自动续跑、账号切换交接及后台任务回调的状态显示。
产品版本 **4.0.12**，通信协议保持 **v74**，Claude Agent SDK 保持 **0.2.157**。

### 本次更新

- **Goal 自动续跑**：上一轮原生任务已结束、页面内容仍在发送时，正确接续下一轮，
  避免实际仍在工作却显示空闲或已打断。连续快速续跑时，通过历史补齐缺失内容。
- **重连恢复**：恢复缺少本地运行记录的活动 Goal 前，同时核实日志中的续跑轮次和
  共享 daemon 的实时状态；只接回已有任务，不重新提交用户输入。
- **账号切换交接**：下一轮已开始时，由下一轮接手账号切换，避免上一轮的收尾逻辑
  误打断下一轮或将两轮合并。保留交接期间已读取的事件及用户停止操作。
- **后台回调纠正**：首次读到失败／中断不立即定案，间隔至少 30 秒再次核实；
  确认失败后仍在原有 24 小时窗口内查询同一回调，后续恢复运行或正常完成时纠正状态。
  正常完成后清除错误提示，后台任务面板不再保留已经送达的条目。
- **旧记录恢复**：已知回调 ID 的旧失败／未确认记录获得一次 24 小时修复查询窗口。
  窗口与核实状态跨重启保留；不重发回调、不重跑命令，也不猜测丢失的回调 ID。

### 升级与验证

安装器管理的部署在独立终端运行：

```bash
cc-remote update --check
cc-remote update --version 4.0.12
```

`cc-remote update` 选择最新稳定版。设备会核对配对的 Relay，必要时先更新 Relay + Web；
其他设备各自更新。用户安装预构建产物，无需运行测试或前端构建。
已启用任务 MCP 的账号，可按
[异步任务指南](https://github.com/muggle-stack/cc-remote/blob/v4.0.12/docs/async-tasks.md)
执行 `cc-remote tasks refresh`，让现有客户端加载新版工具。升级不会自动启用 MCP。

本地完整检查通过：**5735 项测试通过、4 项预期跳过**，Web 构建、可靠性测试、lint
及脚本检查通过。账号切换修复覆盖 4 种确定性竞态；未新增真实模型调用验收。

发布产物包含 Linux Relay、Linux/macOS Wrapper 的 x86_64 与 arm64 包，Relay 内含 Web。
Desktop 和实验 DSH 安装包不在本次 Release 中。

## English

v4.0.12 corrects Codex Goal continuation, account-switch handoff and background
callback state reporting. Product version **4.0.12**, wire protocol **v74**,
Claude Agent SDK **0.2.157**.

- Keep automatic turns running while the preceding turn's output drains. Recover
  gaps from rapid continuations through history instead of showing false idle or
  interrupted states.
- Recover an active Goal after reconnect only when its rooted rollout continuation
  and exact live shared-daemon turn agree. Recovery attaches to existing work
  without resubmitting user input.
- Transfer account-switch recovery to an already-started successor. Preserve the
  predecessor's completion, in-flight stream events, separate turn identity and
  explicit Stop behavior.
- Confirm a negative callback status with another read at least 30 seconds later.
  Continue checking the same failed callback within its original 24-hour window;
  later progress or successful completion corrects its receipt and task panel.
- Give legacy failed/unconfirmed receipts with known callback IDs one durable,
  bounded reconciliation window. Never resend callbacks, rerun commands or guess
  a missing callback identity.

### Upgrade and validation

For managed installations, run `cc-remote update --check` followed by
`cc-remote update --version 4.0.12` in an independent terminal. Plain
`cc-remote update` selects the latest stable release. Each device checks and, if
needed, updates its paired Relay + Web before updating itself; other devices
update separately. Installation uses prebuilt assets without local tests or builds.
For accounts with the task MCP enabled, use `cc-remote tasks refresh` as described
in the [task guide](https://github.com/muggle-stack/cc-remote/blob/v4.0.12/docs/async-tasks.md)
to load the updated tools in existing clients. Upgrades do not enable the MCP.

The full local gate passed: **5735 tests passed, 4 expected skips**, plus Web
build/reliability/lint and shell checks. Four deterministic regressions cover the
account-switch races; no new live model-call acceptance is claimed.

Assets include Linux Relay and Linux/macOS Wrapper packages for x86_64 and arm64,
with Web bundled in Relay. Desktop and experimental DSH installers are not included.
