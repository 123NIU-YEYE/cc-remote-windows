# cc-remote v4.0.29

## 中文

本版更新 Claude/Codex 的新会话界面，并补齐发送第一条消息前的命令、权限与扩展控制。
通信协议升级到 **v79**；Claude Agent SDK 保持 **0.2.157**。

### 新会话与命令

- Code 页面使用紧凑、随内容增高的输入框和当前 Claude/Codex 图标，账号、目录、附件、模型、思考强度、速度与权限控件采用统一布局。
- 新会话与已有会话共用斜杠命令分发规则。本地设置不会作为普通正文发送给模型；需要已有会话的命令保留草稿并给出说明。
- Claude 新会话支持权限选择器、`/permissions`、`/plan`、`/normal` 和 Shift+Tab。所选权限随创建请求一起生效，从第一条消息应用；不选择则保留原有默认行为。
- 切换设备、账号或工作空间时重置相关选择。Work 保留独立的界面和固定权限策略。

### 模型、Skills 与扩展

- `/model <id>` 保留用户明确输入的隐藏或供应商模型 ID，不因目录刷新而删除；从选择器选择的模型继续按可用目录校验。
- 思考强度列表与提交前校验使用同一套规则。未知模型或尚未确定的默认模型仅提供“默认”，读取到支持的强度后再显示选项，已支持的选择在刷新后继续保留。
- Code 新会话支持 `/extensions`、`/skills`、`/plugins`、`/apps`、`/mcp` 和 `/hooks`，读取、刷新及管理操作使用草稿选中的账号和工作目录。
- Codex Skills 建议在失败后显示重试入口，重连或目录失效后恢复读取；迟到的旧结果不会覆盖另一个账号或目录，已有草稿继续保留。
- Work 的私有目录在创建后才确定，创建前不会读取其他 Code 目录中的项目扩展。浏览目录不创建模型轮次。

### 升级与附件

**v79 与旧版协议不互通。** 请按[部署流程](https://github.com/muggle-stack/cc-remote/blob/v4.0.29/deploy/README.md)协调更新 Web、Relay 和所有 Wrapper，再重新加载客户端。普通 Wrapper 更新仍保留独立 Claude 服务。

- GitHub Actions 构建并提供 attestation：六个 Relay/Wrapper 平台包、`install.sh` 和 `SHA256SUMS`。
- Android／鸿蒙源码未改动，沿用 v4.0.28 已发布包的原始字节：已签名 Android preview.2（versionCode 2）和未签名鸿蒙 preview.5（versionCode 5）。
- `MOBILE_BUILD_INFO.json` 保留原始构建来源并记录本次复用，`MOBILE_SHA256SUMS` 提供校验值；移动端附件不属于 GitHub Actions attestation 覆盖范围。
- 鸿蒙 HAP 需要使用自己的开发者及设备 Profile 签名，不能直接安装。已有对应版本的用户无需重装原生应用。

本次不提供 iOS 或 Desktop 安装包。发布本身不会更新线上服务或已安装应用。

### 验证范围

PR #77 的最新功能提交通过 Web/Python CI 和完整本地检查：6,331 项 Python 测试通过、5 项预期跳过；Node 24 Web 构建、可靠性检查、Lint、Ruff、Bash 语法及 ShellCheck 通过。

Chromium/WebKit 回归覆盖新会话命令、Claude 权限与首条请求、模型 ID 和强度在目录刷新后的行为、Skills 重试及扩展账号／目录隔离。SDK 权限测试使用替身客户端验证连接前的配置。本次发布验收不调用真实模型，也不包含移动端真机或线上部署验收。

## English

This release refreshes the Claude/Codex new-chat composer and makes commands,
permissions and extension controls available before the first message.
Wire protocol advances to **v79**; Claude Agent SDK remains **0.2.157**.

### Changes

- Use a compact, growing Code composer with current engine icons and consistent
  account, directory, attachment, model, effort, speed and permission controls.
- Share slash-command routing with active conversations. Local commands remain
  local; session-dependent commands preserve the draft and explain what is needed.
- Select Claude permissions before creation through the picker, `/permissions`,
  `/plan`, `/normal` or Shift+Tab. Apply the selected mode atomically to the first
  message, preserve inherited defaults and Work policy, and reset choices across
  device, account and surface changes.
- Preserve explicitly typed hidden/provider model IDs across catalog refresh.
  Effort options and validation share one capability list: unknown models and
  unresolved defaults offer only the inherited default, while discovered supported
  choices survive refresh and reach the first query.
- Open extension catalogs from new Code chats, with reads, refreshes and management
  scoped to the draft account and directory. Recover skill discovery after errors
  or reconnects without losing the draft or accepting stale cross-scope responses.
- Keep Work's private-directory boundary. Pre-session Work does not discover
  project extensions from an unrelated Code directory; catalog browsing does not
  create a model turn.

### Upgrade and packages

**Protocol v79 is incompatible with older peers.** Follow the
[deployment procedure](https://github.com/muggle-stack/cc-remote/blob/v4.0.29/deploy/README.md)
to coordinate Web, Relay and all Wrapper upgrades, then reload clients. Ordinary
Wrapper upgrades preserve the independent Claude service.

GitHub Actions builds and attests six Relay/Wrapper bundles, the installer and
checksums. Unchanged native sources reuse the v4.0.28 mobile binaries byte-for-byte:
signed Android preview.2 and unsigned HarmonyOS preview.5. Mobile metadata preserves
original build provenance and records reuse; mobile checksums are separate and
these assets are not GitHub Actions attested. The HAP requires your own
developer/device signing profile. Existing mobile users need no native reinstall.

No iOS or Desktop installer is included. Publishing does not deploy services or
update installed applications.

### Validation

PR #77's latest feature commit passed Web/Python CI and the full local gate:
6,331 Python tests with 5 expected skips, Node 24 Web build/reliability/Lint,
Ruff and shell checks. Chromium/WebKit regression checks cover command routing,
Claude creation permissions, model/effort refresh behavior, skill retries and
extension account/directory isolation. SDK permission tests use a stub client to
verify configuration before connection. Release acceptance sends no live model
prompts and does not include native mobile device or production deployment checks.
