# cc-remote v4.0.26

## 中文

本版新增可自定义的外观面板，并改善主题中加粗、链接和代码的可读性。
通信协议保持 **v78**，与 v4.0.25 相同；Claude Agent SDK 保持 **0.2.157**。

### 外观与阅读

- 在「更多设置 → 外观」中实时调整强调色、背景色、文字色和字体。
- 每个引擎的浅色／深色分别保存在当前浏览器，支持跟随系统、跨标签页同步及旧主题迁移。
- 「恢复默认」仅重置当前引擎、当前明暗模式的颜色与字体；切换配色预设保留字体选择。
- 配色与字体菜单采用统一的圆角浮层和对齐的示例。取色器支持触摸拖动、键盘、常用色与 HEX 输入。
- 根据实际颜色修改自动显示「自定义」，无需额外切换；颜色对比不足时提示调整，设置面板本身保持可读。
- Codex 浅色默认使用柔和的紫色系，与深色模式的视觉风格协调。
- 六款预设为加粗文字、链接、行内代码及选中文字提供独立颜色；开启全局加粗后仍保留正文层次，代码继续使用等宽字体。

### 升级与附件

按[部署流程](https://github.com/muggle-stack/cc-remote/blob/v4.0.26/deploy/README.md)更新已安装服务并重新加载 Web 客户端。本版没有跨协议升级；普通 Wrapper 更新仍保留独立 Claude 服务。

- 六个 Relay/Wrapper 平台包、`install.sh`、`SHA256SUMS` 由 GitHub Actions 构建并提供 attestation。
- `cc-remote-android-v4.0.26.apk`：已签名，沿用原签名身份；原生版本保持 `0.1.0-preview.2`（versionCode 2）。
- `cc-remote-harmony-v4.0.26-unsigned.hap`：原生版本保持 `0.1.0-preview.5`（versionCode 5）；**未签名，需使用自己的开发者及设备 Profile 签名，不能直接安装。**
- `MOBILE_BUILD_INFO.json`、`MOBILE_SHA256SUMS` 记录移动端源码提交和校验值；移动端附件从本 tag 的受跟踪源码本地构建，不属于 GitHub Actions attestation 覆盖范围，也不包含私人签名材料或推送服务密钥。

Android preview.2 与鸿蒙 preview.5 用户无需为本次外观更新重装原生应用，重新加载已更新服务的页面即可。本次不提供 iOS 或 Desktop 安装包。发布本身不会更新线上服务或已安装应用。

### 验证范围

- 完整本地检查：6,219 项 Python 测试通过、5 项预期跳过；Node 24 Web 构建、可靠性检查、Lint、Ruff、Bash 语法及 ShellCheck 通过。
- Chromium／移动 WebKit 检查覆盖主题迁移、独立保存、跨标签页同步、重置、键盘及触摸控制、窄屏布局；最终可读性、加粗与代码块检查共 8 项通过。
- Android 单元测试、Lint、构建、签名与对齐检查，以及鸿蒙 Release 编译和包内容检查通过。

浏览器检查不替代所有原生 WebView 真机验收。本次没有重新验证完整 Android／鸿蒙设备流程，也未发送模型测试消息。

## English

This release adds an editable Appearance panel and improves emphasis, links and
code readability. Wire protocol remains **v78**, the same as v4.0.25; Claude
Agent SDK remains **0.2.157**.

### Changes

- Edit accent, background, text colors and fonts with immediate preview from
  **More settings → Appearance**.
- Save light/dark styles separately for each engine in the current browser,
  migrate existing themes, follow system mode and synchronize browser tabs.
- Reset only the current engine and visible mode. Selecting a preset preserves
  the font; the custom label follows actual color edits.
- Use themed, rounded palette/font menus with aligned samples and a color picker
  supporting touch, dragging, keyboard controls, common swatches and HEX input.
- Keep the editor readable when users choose low-contrast colors and show a
  contrast hint. Code retains its monospace font.
- Coordinate Codex's light default with its purple identity. Give bold text,
  links, inline code and selections distinct colors across all six presets,
  including when global bold text is enabled.

### Upgrade and packages

Follow the [deployment procedure](https://github.com/muggle-stack/cc-remote/blob/v4.0.26/deploy/README.md)
and reload the Web client. No wire-protocol migration is needed from v4.0.25.
Ordinary Wrapper upgrades preserve the independent Claude service.

GitHub Actions builds and attests six Relay/Wrapper bundles, the installer and
checksums. The signed Android APK (unchanged preview.2, versionCode 2) and unsigned
HarmonyOS HAP (unchanged preview.5, versionCode 5) are built locally from this tag.
`MOBILE_BUILD_INFO.json` and `MOBILE_SHA256SUMS` record source and hashes; mobile
assets are not GitHub Actions attested. The HAP requires your own developer/device
signing profile and cannot be installed directly.

Existing Android preview.2 and HarmonyOS preview.5 users need no native reinstall
for this release. No iOS or Desktop installer is included. Publishing does not
deploy services or update installed applications.

### Validation

The full local gate passed: 6,219 Python tests with 5 expected skips, Node 24 Web
build/reliability/Lint, Ruff and shell checks. Chromium/mobile WebKit checks cover
migration, persistence, reset, keyboard/touch controls and narrow viewports; the
final content-contrast, bold-text and code-block run passed all eight cases.
Android tests, Lint, build, signature and alignment checks passed, as did the
HarmonyOS Release build and package checks.

Browser checks do not replace native WebView device acceptance. Full Android and
HarmonyOS device flows were not rerun for this release; no model prompts were sent.
