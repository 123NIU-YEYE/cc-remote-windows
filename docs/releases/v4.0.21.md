# cc-remote v4.0.21

## 中文

产品版本 **4.0.21**，通信协议 **v76**，Claude Agent SDK 仍为 **0.2.157**。
本版合入 PR #69 的会话 Artifacts、导航和界面改进，以及全部审查修复。

### 变化

- **会话 Artifacts**：集中查看当前会话的上传附件和 AI 交付文件，按日期分组，
  图片按需加载缩略图。列表与预览分开，返回时保留列表位置；原有目录文件浏览不变。
  查找更早文件只读取历史，不启动模型。已删除的旧临时附件无法恢复。
- **文件隔离与存储**：冷会话也会校验设备、账号、引擎及 Code/Work 归属。
  持久附件副本限制为每会话 256 MiB / 512 个、每 Wrapper 状态目录 2 GiB / 4096 个，
  并预留 256 MiB 磁盘空间。满额保留已有附件，不阻塞向引擎提交附件；
  中文等多字节长文件名按实际字节数安全截断，显示名称不变。
- **独立侧聊与快捷键**：Cmd/Ctrl+Shift+E 只控制居中侧聊，保留底下的文件预览与编辑状态。
  Cmd/Ctrl+1/2 可在询问弹窗、居中侧聊打开时切换 Claude/Codex，返回时恢复草稿、
  询问选项、滚动位置及侧聊布局，不代答、不取消任务。
- **界面细节**：手机询问弹窗居中并避让键盘；使用带来源说明的 Claude/Codex 图标，
  Claude 工作动画与完成图标保持一致，完成后可点击或用键盘重播，尊重减少动态效果设置。
  提示条更紧凑，移除引擎选择器箭头及多余选中背景。
- **鸿蒙外壳**：聊天页不再注入客户端设置等原生专属入口，登录页和加载错误页仍可设置服务地址。
  鸿蒙外壳版本为 `0.1.0-preview.4`（versionCode 4）；Android 外壳未改动，仍为 preview.2。

### 安装包与升级

| 附件 | 用途 |
| --- | --- |
| `cc-remote-android-v4.0.21.apk` | 已签名的 Android 预览版，Android 8.0+；沿用原签名身份 |
| `cc-remote-harmony-v4.0.21-unsigned.hap` | 鸿蒙原生 ArkWeb 预览版；需自行使用开发者账号与设备 Profile 签名，不能直接安装 |
| 六个 Relay/Wrapper 平台包、`install.sh`、`SHA256SUMS` | Linux Relay、Linux/macOS Wrapper，含 x86_64 和 arm64 |
| `MOBILE_SHA256SUMS`、`MOBILE_BUILD_INFO.json` | 移动包校验值、源提交及构建信息 |

移动包由维护者从本次发布提交的受版本管理源码构建；不属于 GitHub Actions 构建证明范围。
公开 HAP 不包含个人设备签名、开发者凭证或推送服务私钥。本版不提供 iOS 或 Desktop 安装包。

**从 v4.0.20 升级时，Web、Relay、所有 Wrapper 必须一起升级到协议 v76。**
在独立终端按仓库部署流程执行，避免只更新某一个协议层：

```bash
cc-remote update --check
cc-remote update --version 4.0.21
```

发布版本不会自动更新现有服务或手机。普通 Wrapper 更新保留独立 Claude 会话服务；
鸿蒙原生外壳变化需要重新签名并覆盖安装，纯 Web 更新由服务端提供。

### 验证与边界

- 合并前完整本地检查通过：6,046 项 Python 测试通过、4 项预期跳过；
  Ruff、Node 24 Web 构建/可靠性/静态检查、Bash 语法及 ShellCheck 通过。
- UI 已通过 30 项 Chromium/mobile WebKit 检查；鸿蒙通过 10 项 Node 测试和 21 项浏览器适配检查。
- 发布流水线重新运行 Web/Python 检查，并验证六个平台包的安装、导入及清单。
- Android 完整真机验收仍未完成；本版不新增 Android 原生推送、下载管理或相机/麦克风。
  鸿蒙锁屏通知及点击返回曾经真机确认，进程被终止等全部推送场景尚未完整验收。
  WORK 分类仍需要各应用自行取得华为批准；本版不改变该要求，也不承诺解决鸿蒙侧栏帧率问题。

## English

Product **4.0.21**, wire protocol **v76**, Claude Agent SDK **0.2.157**.
This release includes PR #69 and its review fixes.

- Add session-scoped Artifacts for uploads and delivered files, with date groups,
  bounded thumbnails, separate previews and list-position restoration. The directory
  browser remains independent. Historical discovery does not start a model turn.
- Enforce device/account/engine/Code/Work ownership for cold-session file reads.
  Bound private copies to 256 MiB / 512 files per session and 2 GiB / 4096 files per
  Wrapper state directory, reserving 256 MiB of disk. Preserve existing copies when
  full and keep attachment submission working if optional copying fails. Bound
  stored filenames by UTF-8 bytes while preserving their display names.
- Keep centered side chat independent of file previews. Cmd/Ctrl+Shift+E only
  toggles side chat; Cmd/Ctrl+1/2 switches Claude/Codex across dialogs while
  preserving unfinished questions, drafts, scroll positions and side-chat layouts.
- Center mobile questions above the keyboard, use attributed engine icons and a
  replayable Claude completion animation, respect reduced motion, and refine notices.
- Remove Harmony-native chat controls while retaining setup on login/load errors.
  Harmony advances to preview.4; the unchanged Android shell remains preview.2.

Upgrade **Web, Relay and every Wrapper together** from protocol v74 to v76.
Publishing does not deploy services or update phones. Native Harmony changes need
a newly signed, in-place HAP installation. The public HAP is **unsigned** and
requires the user's own developer/device profile; the Android APK retains its
release signing identity. Mobile builds are maintainer-local, with provenance in
`MOBILE_BUILD_INFO.json`, separate from the CI-attested core bundles.

The complete pre-merge local gate passed with 6,046 Python tests and 4 expected
skips. Prior UI validation includes 30 Chromium/mobile WebKit checks, plus 10
Harmony Node tests and 21 browser adapter checks. Release CI reruns Web/Python and
package smoke checks. Full Android device acceptance and all process-terminated
Harmony push scenarios remain pending. WORK push requires Huawei approval for
each application. No new frame-rate guarantee, Android native push, download
manager, camera/microphone support, iOS package or Desktop installer is included.
